# 公众号爆款选题（topic-research）

> 扩展选题能力：在 GitHub 热榜 / AI 媒体热点之外，增加**公众号生态内**的选题来源。
> 公众号爆款数据没有公开 API，靠"抓取聚合源 + 人工投喂 + 统一拆解"三条路。

## 三条选题路径
### ① 赛道爆款分析（对应 baokuan-article-analysis）
- 用户给一个赛道关键词（如「AI 工具」「程序员副业」）→ 宿主 Agent 用 **WebFetch / general_search** 检索该赛道的公众号爆款文章（可查新榜、公众号聚合平台、行业榜单）。
- 命中后按 `scripts/analyze_viral_article.py` 的 8 个维度拆解：标题公式 / 爆款点 / 开头钩子 / 结构骨架 / 数据支撑 / 写作风格 / 可复用模板 / 风险提示。
- 结论落到「我们账号能借鉴什么、差异化空间在哪」。

### ② 低粉高阅读收录（对应 gzh-explosive-content-detector）
- 关注「粉丝少但阅读量高」的号——这类文章的选题/标题通常有真实爆款基因，比大号更值得学。
- 收录方式：用户在日常刷到低粉高阅读的文章时贴给 Agent → 走同一套拆解 → 进选题候选池。
- 关键词触发：「收录一篇爆款」「这篇为什么火」「低粉高阅读」。

### ③ 用户投喂（B 类输入延续）
- 用户直接把一篇爆款文章/链接发来 → 拆解 → 入库（选题候选池记录在 `.workbuddy/memory/`）。

## 拆解产出物
每次分析输出一份 `outputs/topic_analysis_<日期>.md`，包含：
- 标题公式判断（勾选）
- 8 维度拆解
- 可复用模板（抽象成可套用的骨架）
- 我们能借鉴的 1-2 个选题方向

## 与主流水线的衔接
拆解出的「选题方向」→ 如果用户选定 → 按 B2（给题目）或 B1（给题目+论点）进入 7 步流水线：
选主题 → 排版 → 校验 → 预览 → 标题（用 `generate_titles.py`）→ 存稿。

## 选题纪律（公众号特性）
- 公众号是私域（老读者），选题要**对已关注的人持续有增量价值**，不能只蹭热点。
- 爆款 = 50% 选题 + 30% 标题封面 + 20% 内容表达——选题权重最高，别在标题上省时间但更别在选题上偷懒。
- 宁可发一篇深度，不水三篇浅的（账号定位是「研究员的日常记录」，重质不重量）。
